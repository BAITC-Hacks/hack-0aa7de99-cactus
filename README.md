# Track 8: локальный протокол совещания

Прототип для macOS Apple Silicon. Аудио и текст обрабатываются локально: Whisper через MLX, диаризация через локальную модель pyannote, извлечение поручений через локальный Ollama. Приложение не вызывает внешние API. Все модели нужно скачать заранее, пока есть доступ к сети, и указать **локальные пути**.

## Запуск

```bash
brew install ffmpeg
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# В отдельном терминале: ollama serve; затем ollama pull qwen2.5:7b
export ASR_MODEL=/absolute/path/to/local/mlx-whisper-model
export DIARIZATION_MODEL=/absolute/path/to/local/pyannote-pipeline
export OLLAMA_MODEL=qwen2.5:7b
streamlit run app.py
```

Для pyannote.audio 4.x нужен локальный pipeline с весами segmentation, embedding и clustering. Рабочий пример на этом Mac: `pyannote-community/speaker-diarization-community-1`, скачанный в `models/diarization`. Код передаёт уже декодированный WAV как массив, поэтому TorchCodec не загружает системные библиотеки FFmpeg. Если диаризация недоступна, приложение сообщает об этом; говорящие не подставляются фиктивно. Для проверки интерфейса без тяжёлых моделей можно вставить вручную транскрипт с метками говорящих. Такой прогон проверяет извлечение и экспорт, **не проверяет** ASR и диаризацию.

## Сценарий

1. Загрузить MP3/WAV или вставить размеченный транскрипт.
2. Запустить обработку, проверить имена Speaker 1, Speaker 2 и назначить их людям при необходимости.
3. Проверить поручения по цитате и времени; отредактировать неверные поля.
4. Скачать DOCX протокол.

Приложение выделяет поручение, ответственного, исходный срок, доказательство и вопрос на уточнение. Если в записи назван ответственный, который не говорил, например юрист Ерлан, его имя сохраняется отдельно от говорящего, произнёсшего поручение. Сроки «до пятницы» сохраняются как исходная фраза, без выдуманной календарной даты. Вопросы на уточнение — дополнительная возможность, основной результат — протокол и список поручений.

## Ограничения текущего прототипа

- Подключения к Teams/Zoom/Meet и потокового режима нет; поддерживается путь через запись, предусмотренный ТЗ.
- На этом Mac проверены MLX Whisper 0.4.3 и pyannote.audio 4.0.7 на первых 45 секундах записи №1. Результаты локального прогона хранятся в `smoke/` и исключены из Git.
- Качество русского, казахского, смешанной речи и диаризации необходимо измерить на двух записях из папки `innovations` и отдельной смешанной записи: две комплектные записи преимущественно русскоязычные.
- Локальная модель может ошибаться; пользователь утверждает протокол после проверки источников.

## Структура

- `app.py`: интерфейс, загрузка и DOCX.
- `pipeline.py`: локальные ASR, diarization, извлечение, проверка доказательств и полноты.

Ни запись, ни имена участников не следует коммитить в публичный репозиторий без анонимизации. README, воспроизводимость и демонстрация полноценного локального прогона дают отдельные 25 баллов по ТЗ.

## Локальный smoke test ASR и диаризации

Один и тот же 45-секундный WAV (`smoke/meeting1_first45s.wav`) используется обоими этапами. Папки `models/` и `smoke/` остаются локальными. Модель диаризации можно загрузить так:

```bash
.venv/bin/python - <<'PYCODE'
from huggingface_hub import snapshot_download
snapshot_download('pyannote-community/speaker-diarization-community-1', local_dir='models/diarization')
PYCODE
export ASR_MODEL="$PWD/models/whisper"
export DIARIZATION_MODEL="$PWD/models/diarization"
```

`pyannote.audio 4.x` возвращает объект с `exclusive_speaker_diarization`; версия 3.x возвращала непосредственно `Annotation`. Код принимает оба формата. Для итогового транскрипта используется exclusive diarization, удобная для назначения одного говорящего каждой ASR-реплике. На короткой реплике в конце клипа метка говорящего может быть ошибочной; её нужно проверить по записи.
